# Billing and AI allowance reliability — tasks 01 and 02

**Scope/status:** Reviewable implementation on `feat/billing-reliability`, based on PR #87. Existing signed webhooks, current-state retrieval, account leases and atomic receipts are retained. This group fixes Free-plan failure/cancellation guidance, adds delayed-payment/pause/resume event reconciliation and verifies real PostgreSQL contention for both premium features. It does not replace the earlier AI cancellation work in PRs #59/#60.

**Prerequisites:** Use a disposable confirmed owner, another unrelated account, an isolated test database and a Stripe sandbox. Configure the existing server-only billing settings and all subscribed event types from [Stripe setup](../../features/stripe-billing.md). Never use live keys, payments, customer IDs or production user data for these checks. Local database checks require PostgreSQL server tools (`pg_config`, `initdb`, `postgres`, `psql`) on PATH; they create and remove their own cluster and ignore app/PG connection variables. They cannot connect to a supplied database URL.

Use the matching PR preview hostname in place of `mydevstudio.vercel.app`, and your disposable owner username in place of `test-owner`. Browser tests use fixtures, not Stripe. Hosted sandbox flows below remain **Not run** until executed with the configured provider.

- `e2e/admin/billing/billing.spec.ts` checks checkout return, Free/past-due/canceled guidance and readiness on desktop/mobile through local fixtures.
- `tools/scripts/test-billing-postgres.mjs` uses actual independent PostgreSQL connections. It is distinct from PGlite tests and makes no Stripe/OpenAI call.

The Stripe integration remains sandbox-only. Tax registrations, refunds, disputes, fraud handling and live-payment policy need a separate reviewed launch plan. No live settings are enabled here.
