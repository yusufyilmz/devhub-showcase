# Workspace catalog generation — manual testing

**Scope/status:** Implemented generator for every package discovered through `pnpm-workspace.yaml`, including apps and tools. Hand-written guidance lives in `catalog.template.md`; package references are generated. UI registry markers retain their existing behavior and validation.

**Prerequisites:** Node 24.15+ below 25, pnpm 11 and installed dependencies. No account, database, provider key or browser is required. Use fictional fixture workspaces for failure and symlink checks. Keep existing source templates under version control.

**Manual result:** Not run. Automated evidence is separate. URLs provide repository context; the CLI has no HTTP route.

Symbol inventory does not execute implementation modules. The UI adapter loads the existing pure registry/config metadata for its consistency checks. Generation does not call models, install packages or use the network. A missing template for an already generated catalog is an error: restore its source rather than copying rendered output back into a template. See [CLI usage](../../../tools/cli/README.md#generate-catalogs-for-every-workspace-package).

## Automated evidence

Verified locally on 2026-11-07: all 16 workspace catalogs passed `pnpm check:catalogs`; the UI compatibility check also passed. The full suite passed 677 tests across 191 files, including 13 generator tests. Root/workspace type checking passed all 14 tasks. Targeted code and guide lint checks passed. Fixture tests verify creation, read-only checks, idempotence, discovery/exclusions, static symbols, escaping, CLI failures and path safety.
