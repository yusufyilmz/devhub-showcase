# Fitness login and saved workspace compatibility

**Scope/status:** PR #97 fixed workspace loading after the standalone-to-monorepo deployment move. Accepts stored exercise prescriptions, set history and postponed-workout details while keeping earlier basic records valid. No database migration or record rewrite is required. This does not enable Google OAuth or add standalone exercise editing features.

**Prerequisites:** A disposable confirmed Fitness owner, a different account and a signed-out browser. Use fictional exercise history and postponed workouts in a test database; never edit production records to create fixtures. Fitness currently uses its own Supabase project; Studio sessions on a different hostname do not establish a Fitness session.

**Observed configuration issue during PR #97:** Production Google authorization returned `Unsupported provider: provider is not enabled`. An administrator must enable Google with the appropriate OAuth client in [Fitness Auth providers](https://supabase.com/dashboard/project/dtqqopvrimmlmntnlegx/auth/providers). Configure Google's authorized redirect URI as `https://dtqqopvrimmlmntnlegx.supabase.co/auth/v1/callback`, and allow the Fitness application callback URL in Supabase. Do not change projects or copy another project's secrets to bypass this setup.

Use the production links below after deployment, or replace the origin with the actual HTTPS preview URL and configure its callback. Local Fitness runs at `http://localhost:3002`.
