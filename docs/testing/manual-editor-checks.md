# Manual editor and section checks

Use this guide to review the changes in roadmap tasks 05, 08 and 17 and to test portfolio sections. Each step includes its expected result. Record what actually happened in the PR; these instructions alone are not evidence of a completed manual run.

## Setup

Use a preview deployment and a disposable confirmed account with a private test portfolio. Use fictional content. A new account is needed to see the first-time setup; an existing account normally opens the full editor. Keep a second tab available for conflict checks.

For repeatable local checks without real accounts, OpenAI requests or payments, use the synthetic fixture tests:

```sh
pnpm --filter my-dev-studio build
pnpm exec playwright test e2e/edit/editor-workflow.spec.ts e2e/edit/ai-editor.spec.ts e2e/edit/studio-chat.spec.ts
```

Both desktop Chromium and Pixel 7 emulation run by default. Add `--project desktop-chromium --headed` to watch one desktop run. The test runner starts its own fixture and app servers on ports 3100, 3101 and 3102; keep them free. See [testing setup](../testing.md) for installation and failure artifacts.

Manual AI generation needs an assistant-enabled test account with remaining allowance and configured provider access. Generating a proposal consumes an attempt. The fixture tests simulate the provider and entitlement responses instead.

## Task 05: Guided onboarding

| Step | Action                                                                                                                                                                       | Expected result                                                                                               |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 1    | Open the new account's `/{username}/edit` route.                                                                                                                             | Step 1 shows profession and layout choices; the portfolio is private.                                         |
| 2    | Select Designer's audience under **What kind of work do you do?**.                                                                                                           | The recommended layout becomes Designer. Existing content is retained.                                        |
| 3    | Pick Consultant in the layout cards.                                                                                                                                         | The layout changes, while the profession choice stays Designer.                                               |
| 4    | Select **Use this layout**, then **Skip import · enter manually**.                                                                                                           | Step 2 and the profile fields are available without uploading anything.                                       |
| 5    | Enter a valid professional title and short introduction. In **PDF**, choose Compact under **CV layout**.                                                                     | Both profile content and the independent CV choice are held in the draft.                                     |
| 6    | Select **Back to layout**, change the layout, then **Use this layout** again.                                                                                                | The title, introduction and Compact CV choice remain intact.                                                  |
| 7    | Select **Import a CV** and exercise a failed import using the fixture scenario.                                                                                              | The error is visible and existing fields remain unchanged. **Skip import · enter manually** still works.      |
| 8    | Wait for **Recovery saved in this tab**, reload and accept the browser's leave warning if shown. Inspect **Review recovered work**, then choose **Restore recovered draft**. | Entered values, selected tab, profession and setup step return. Nothing is published by restoring.            |
| 9    | Select **Review draft**.                                                                                                                                                     | Step 3 explains review, visibility and explicit saving. The draft preview remains available below the editor. |
| 10   | Select **Finish setup** or **Continue in full editor**.                                                                                                                      | Guidance closes without discarding the draft or automatically saving it.                                      |
| 11   | Keep publication unchecked and select **Save changes**. Reload.                                                                                                              | The revision advances, the saved data persists, and an anonymous visit to the private portfolio returns 404.  |

The automated onboarding scenario also verifies failed-save retry and the second-tab conflict below. Import responses are simulated; it does not validate a live CV provider.

## Task 08: Autosave and recovery

| Step | Action                                                                                                           | Expected result                                                                                                                                                                                                      |
| ---- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Change a title several times quickly without selecting Save.                                                     | Recovery changes from pending to saved after approximately 500 ms of inactivity. The latest title is retained; server revision and public content do not change.                                                     |
| 2    | Type another value and immediately reload or leave the editor, then return.                                      | Pending work is flushed on exit/navigation and offered for recovery. The browser may ask before leaving unsaved work.                                                                                                |
| 3    | Expand **Review recovered work** before choosing **Restore recovered draft**.                                    | The recovery is inspectable; restoring updates only the local editor and does not save or publish.                                                                                                                   |
| 4    | Run the blocked-storage recovery unit test listed below.                                                         | A failed recovery write stays visible with **Retry recovery save**. Retrying after storage becomes available saves recovery; the UI does not claim success early.                                                    |
| 5    | Exercise the fixture's failed explicit save, then retry **Save changes**.                                        | The error is visible, entered data remains intact, and only the successful retry advances the saved revision.                                                                                                        |
| 6    | In tab A, make an unsaved title change. In tab B, open the same account/portfolio, change the title and save it. | Tab A warns of the newer revision and disables Save where cross-tab notifications are supported. Server revision checks still reject stale saves if notifications are unavailable or another device made the change. |
| 7    | Reload tab A and inspect its older recovery.                                                                     | **Restore recovered draft** is disabled for the stale record. The editor contains tab B's saved version. Recovery remains readable for manual reconciliation.                                                        |
| 8    | Select **Discard recovery**.                                                                                     | Only the recovery is removed; the newer server content stays unchanged. Copy desired text into the current draft manually rather than replacing the newer revision.                                                  |
| 9    | Make another unsaved edit, then use **Sign out** and confirm leaving.                                            | This tab's recovery records are cleared and the editor requires sign-in. Appearance preferences are not deleted. The clearing and exit-flush behavior have separate unit coverage.                                   |
| 10   | Check expiry/corrupt-record tests, and open a separate browser/session.                                          | Expired or structurally invalid records are not restored. Recovery is tab-local with 24-hour expiry, not a cross-device backup.                                                                                      |

```sh
pnpm exec vitest run --project unit packages/ui/src/portfolio/recovery
```

## Task 17: AI change review

| Step | Action                                                                                                                            | Expected result                                                                                                                           |
| ---- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Make a small manual edit so **Undo draft change** is available, then open **AI assistant**. Ask for a title and summary revision. | An authorized account can generate a structured proposal. Generating does not change the draft or saved portfolio.                        |
| 2    | Inspect **Current value**, **Suggested value** and **Compare before and after**.                                                  | Prose is readable and full data remains available, including large values shortened in the readable summary.                              |
| 3    | Before selecting any fields, inspect **Apply selected changes to draft**.                                                         | No fields start accepted and Apply is disabled.                                                                                           |
| 4    | Accept only the **title** field and apply.                                                                                        | Only the title changes in the draft. The rejected summary remains unchanged, and the public portfolio/CV do not update.                   |
| 5    | Select **Undo AI changes**.                                                                                                       | The pre-application draft returns without saving.                                                                                         |
| 6    | Generate another proposal. Use **Accept all proposed changes**, then **Reject all proposed changes**.                             | The accepted count changes accordingly; rejecting all disables Apply and changes no fields.                                               |
| 7    | While a proposal is visible, use **Undo draft change** above the assistant to alter its baseline.                                 | A stale-proposal warning appears and applying is disabled. Generate a fresh proposal to proceed.                                          |
| 8    | Run the malformed-field and revision-mismatch unit tests below.                                                                   | Unsupported, malformed or mismatched proposals are refused without partial changes or changes to private-project publication.             |
| 9    | Apply a fresh accepted change, inspect the draft preview, then explicitly save if desired.                                        | Application and preview remain local until Save; a private portfolio remains private unless publication is explicitly selected and saved. |

## Portfolio sections

Start with a test portfolio containing at least two experience entries, public and private projects, skills, education and languages. Use short text, long text and at least one empty optional section. Check the actual section rather than relying only on a screenshot of the page header.

| Step | Action                                                                                                                                                          | Expected result                                                                                                                                                                                                                                                        |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | In **Section display**, locate a built-in section such as Experience. Change **Display style** to an offered alternative.                                       | Its inline preview and **Preview your draft** use that renderer with the current draft content. Unsupported renderers are not offered.                                                                                                                                 |
| 2    | Under **Included content**, turn off **All items, including future additions** and select one item.                                                             | Only the selected item appears in that portfolio section. Other source records remain in the editor.                                                                                                                                                                   |
| 3    | Uncheck **Show section**.                                                                                                                                       | The section disappears from the portfolio preview; its content is not deleted. Rechecking restores it.                                                                                                                                                                 |
| 4    | Inspect Projects and any section bound to project data.                                                                                                         | Private projects do not appear, even when all source items are selected. Hidden sections remain excluded.                                                                                                                                                              |
| 5    | Open **Custom sections**, choose a **Section starter**, then **Add custom section**. Set **Section name**, add items and enter fictional titles/details.        | The authored section appears in the draft and can be edited without replacing existing sections.                                                                                                                                                                       |
| 6    | Exercise the offered Accordion, Tabs, Carousel or Grid presentation with empty and populated content.                                                           | Accordion reveal is deliberate, tabs switch the intended panel, carousel arrows move content, and empty content produces no broken controls.                                                                                                                           |
| 7    | Exercise relevant media sections with valid media, missing media, long descriptions and descriptive image text.                                                 | Images/layouts remain usable, missing-media states stay readable and unrelated content does not disappear. Script-based embeds may be disabled in the private draft frame; verify their interactive behavior separately on the disposable published preview portfolio. |
| 8    | Duplicate a custom section, edit the copy, then remove only the copy and confirm.                                                                               | The original content remains intact and only the intended section is removed.                                                                                                                                                                                          |
| 9    | In **Section order**, use **Move … up/down** or focus a **Reorder …** handle and use its keyboard controls.                                                     | Ordering updates without requiring dragging. Introduction/contact placement and hidden-section rules remain intact.                                                                                                                                                    |
| 10   | Open **Preview your draft** and check Mobile 375px, Tablet 768px and Desktop 1280px. Repeat affected layouts.                                                   | Order, renderer, selections and unsaved text persist. The portfolio fits its viewport; only intentional carousels and the wider desktop canvas scroll horizontally, not the entire editor page.                                                                        |
| 11   | Check light/dark mode, accents, keyboard focus, touch targets and reduced motion for changed controls.                                                          | Text and controls remain readable and usable without hover-only access.                                                                                                                                                                                                |
| 12   | On a disposable preview portfolio, explicitly save the changes and reload. If publishing is part of the test, publish explicitly and inspect the anonymous URL. | Saved configuration survives reload; public readers see only the saved allowed content. Unsaved changes remain private.                                                                                                                                                |
| 13   | Download the saved CV and inspect its own settings.                                                                                                             | Portfolio-only section order, visibility and selected-item settings do not implicitly redefine the PDF layout/content controls.                                                                                                                                        |
