# Portfolio search and branding

NEXT_PUBLIC_SITE_URL is the canonical platform origin, defaulting to https://mydevstudio.vercel.app. Set it to the production domain in deployment configuration. The profile website field remains an outbound personal link; it does not select the platform canonical URL.

Published username pages generate titles, descriptions, skill keywords, canonical links, Open Graph and Twitter cards, locale metadata, and Person structured data from the current profile. The Person URL is the canonical portfolio URL; external professional links remain sameAs references. Homepage and editor structured data describe MyDevStudio, without embedding an editor's private profile in metadata. Admin and owner editor pages declare noindex/nofollow. Fictional examples retain their existing noindex setting.

Each published profile has a generated /{username}/icon.svg and a 1200 by 630 /{username}/share.png. Both use the current name initials and accent. The same name mark appears in portfolio navigation. Images contain only the published name, professional title and public URL; no remote profile media is fetched by the application. Names are escaped in SVG and rendered as text in sharing images. Missing and private usernames return 404 for both endpoints, even if a browser has an owner session. Asset responses use no-store so application caches do not retain an unpublished identity. Previously downloaded images and search engine caches are outside the application's control.

/sitemap.xml is generated at request time using an anonymous Supabase client, publication filtering and only username/updated_at columns. It contains the homepage and published, valid usernames. It never includes editors, fictional examples, private profiles, profile documents or contact fields. Database reads are paginated in deterministic username order. Database errors fail the request rather than silently serving an incomplete list. Without database configuration it lists only the homepage, not the bundled personal seed. A single sitemap supports fewer than 50,000 published portfolios; partition it before that limit. Sitemap discovery is not a new public account directory UI.

/robots.txt advertises the sitemap and discourages crawling admin, API, auth, owner editor, legacy/example and PDF routes. Robots instructions are crawler guidance, not authorization. Existing server checks and RLS still enforce access. Google indexing and rankings are determined by the search engine. After deployment, the site owner can submit the canonical /sitemap.xml in Google Search Console.

Verification covers anonymous discovery pagination and filters, canonical identity independent of external website links, Unicode initials, SVG escaping, actual generated PNG dimensions, and 404 responses for private/missing profile assets. Local browser fixtures exercise metadata, platform/editor separation and sitemap exclusions without production accounts.
